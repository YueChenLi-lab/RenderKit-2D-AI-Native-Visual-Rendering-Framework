# 下一版本路线图

v0.1 以规则和共享 IR 验证可运行的内容 → Web/PPTX → 审计 → 修复闭环。当前测试执行状态见 [VALIDATION.md](VALIDATION.md)，本文件不把规划功能描述为已交付能力。

## 优先：完善渲染与审计证据

- 增加可选 LibreOffice / PowerPoint 渲染适配器，产出真实 PPTX 页面图像，并与结构检查分别报告。
- 为 CJK 与跨平台字体建立可重复的字体配置和视觉基线，减少 Windows / Linux 之间的换行差异。
- 将更多组件的文本测量由估算改为目标渲染器实测，增加复杂表格、长公式和多层架构压力样本。
- 增加输出文件结构验证的覆盖范围，报告 Office 兼容性问题和导出资产限制。

## 其次：扩大安全修复范围

- 可追溯的跨页拆分，维护来源、保留约束、页间引用与原始 ID 映射。
- 对复杂结构提供受限布局优化，修复前后自动比较内容哈希与图表数值。
- 把明确不可修复的输入与未找到修复方案的输入分别报告，避免把启发式失败当成不可能证明。
- 组件级修复预览及可接受的差异列表，保留人工决策记录。

## 再次：内容与 Agent 扩展

- 支持更完整的 Markdown / front matter、结构化引用和连续数值 XY 图表模型。
- 可选模型规划适配器：结构化输入输出、无密钥时规则回退、显式网络授权、内容保全校验。
- 更丰富的机构主题、可复用组件组合和用户自定义 renderer registry。
- 增加批量任务、稳定 npm 包接口与版本迁移工具；发布前移除 `private` 并完成发布流程审查。

不计划在近期自行实现字体排版引擎、图形栅格化、大模型训练或强化学习。审美分数将继续作为可解释的辅助信号，而不是科学内容正确性的证明。
